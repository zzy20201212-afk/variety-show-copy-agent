# 企业展示指南：如何讲好这个 AI Agent 作品

> 面向求职 / 面试 / 项目汇报场景。核心目标不是"我用了什么工具"，而是"我解决了一个真实业务问题，并且懂得背后的方法论"。

---

## 一、先想清楚：你要向企业证明什么

企业招聘 AI 方向的人，最看重三件事：

1. **业务理解**：你能不能把一个模糊的业务需求，拆解成可执行的技术方案。
2. **方法论**：你懂不懂提示词工程、RAG、结构化输出、可扩展设计这些底层原理，而不是只会点按钮。
3. **落地能力**：你能不能把方案真的做出来、跑起来、给别人用。

这个作品恰好覆盖了这三点——所以展示时，一定要**围绕这三条主线讲**，不要陷入"我用了 Coze / 我写了 HTML"这种工具细节。

## 二、讲故事的框架（万能四段式）

任何技术面试都能套用：

```
① 问题  → 综艺上热搜，30分钟内要产出十几条不同人设的文案
② 方案  → 把人设抽象成风格单元 + few-shot + 结构化提示词 + 结构化输出
③ 成果  → 一个可交互的在线 Demo，参数化控制，批量产出
④ 价值  → 效率提升、风格稳定、新人即开即用、可扩展零代码
```

## 三、三个版本的话术

### 🚀 30 秒电梯版（自我介绍时用）

> 我做了一个面向综艺宣发的 AI Agent。痛点是节目上热搜时，运营要在半小时内产出十几条不同账号人设的微博文案——官号要克制、粉丝号要真情实感、素人要像路人。我把这些"人设"抽象成可复用的风格单元，用真实爆款文案做 few-shot，再通过结构化提示词和输出格式约束，让模型稳定地产出可直接发布的文案，而不是随机发挥。整个工作流支持六维参数控制，新增一个人设只需要加一条描述，不用改代码。线上有可交互的 Demo 可以直接体验。

### 📋 3 分钟详版（正式面试时用）

分五步讲：

1. **背景**：综艺宣发是高频、重复、强时效的创作场景。
2. **拆解**：我把这个需求拆成"风格抽象 + 提示词模板 + 知识库 + 结构化输出"四个模块。
3. **设计**：重点讲提示词的四段式结构（角色/风格库/硬约束/输出格式），以及 few-shot 怎么锁定风格。
4. **演示**：打开线上 Demo，现场输入参数跑一遍，并打开"提示词设计"标签页，让面试官看到 Agent 内部构造的提示词——这是最有说服力的一刻。
5. **价值与扩展**：讲可扩展性（新增人设零代码、换模型零改动），以及未来规划（接真实 API、多 Agent 协作）。

### 📊 5 分钟汇报版（项目汇报 / 上级沟通时用）

按 README 的章节结构讲：背景痛点 → 方案对比（表格）→ 架构图 → 关键技术设计 → 未来规划。

## 四、高频追问 & 应对

| 面试官问 | 应对思路 |
|---|---|
| **"为什么不直接用一句话让 ChatGPT 写？"** | 一句话提示不稳定，风格漂移、格式不统一。我把提示词工程做成结构化模板，用 few-shot 锁定风格、用输出格式约束保证可解析，这是"从提示到 Agent 工作流"的升级点。 |
| **"怎么保证生成质量稳定？"** | 三层保障：① 风格库真实范例做 few-shot；② 硬约束（角度不重复、措辞克制、带话题标签）；③ 结构化输出 + 正则解析 + 异常兜底。 |
| **"怎么扩展新综艺 / 新人设？"** | 知识库与代码解耦。新增综艺加一条信息，新增人设加一条描述，生成逻辑零改动。 |
| **"换大模型（GPT/DeepSeek/豆包）怎么办？"** | 生成节点松耦合，只改接口配置，提示词与解析层完全复用。 |
| **"演示版和生产的区别？"** | 演示版为了离线可跑，用内置模板引擎模拟 LLM、用本地知识库模拟联网搜索；生产环境这两处分别替换为大模型 API 和搜索 API，链路不变。主动说明这点反而加分——说明你分得清 demo 和 production。 |
| **"数据 / 效果怎么量化？"** | 如果做过真实测试，给出数字（如"单次产出从 40 分钟降到 3 分钟""12 条文案 0 返工"）。没有数字就说设计目标，别编。 |

## 五、现场演示技巧（关键）

1. **先备好一个完整案例**：提前在 Demo 里填好"综艺名 = 这是我的西游2、话题词 = 邵兵说自己是上古老登、剧情 = 邵兵早餐自嘲"，现场一键生成，别现场临时想输入。
2. **必点"提示词设计"标签页**：让面试官看到 Agent 内部构造的提示词，这比结果本身更能体现你的方法论。
3. **主动讲架构图**：对着"架构设计"标签页，用 30 秒讲清楚六个节点的数据流。
4. **打开 GitHub 仓库**：展示 README 文档、清晰的目录结构、规范的 commit，证明工程习惯。

## 六、作品集打包建议

一个完整的作品集链接，应该包含：

1. **在线 Demo**（能点、能玩）
2. **GitHub 仓库**（能看代码、看文档）
3. **一段文字说明**（问题 → 方案 → 价值）

简历上推荐这样写：

> **综艺热搜文案生成 Agent**（独立项目）
> - 独立设计并部署 AI Agent 工作流，解决综艺宣发场景的批量文案生产问题
> - 核心：多账号人设抽象 + few-shot 风格锁定 + 结构化提示词 + 结构化输出解析
> - 技术栈：原生 JS / GitHub Pages / 可扩展知识库设计

## 七、最后的心态建议

企业面试看的是**你解决问题的思路**，不是作品多大。一个"小而完整、逻辑清晰、能讲透"的项目，比一个"大而空洞、自己都说不清"的项目强得多。把这份作品从头到尾讲顺、把每个设计决策的原因想清楚，你就已经比大多数候选人专业了。
